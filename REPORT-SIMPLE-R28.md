## Codex and critics, line by line
- **P1-1** (a recent edit masquerades as confirmation): `asked_at` is the only date that can confirm; general edits never renew it; no `asked_at` is unconfirmed; a future date is not confirmation.
- **P1-2** (the list promises actions before freshness is known): confirmation is resolved before a request is listed; the separate "recheck" line is Uni's to reconcile; held-back asks say "Checking…".
- **P1-3** (summary invalidation): scoped to the node's own tasks, with closures counted (see 4). Limitation below: a plain state change on a live task has no date in the vault, so it cannot trigger; only `asked_at` and a closure can.
- **P2-5** (compact): the strip always opens **one panel** (the inline mode is gone). Its summary is folded to a date line, its footer is outside what scrolls, and its first request is whole in view. A task opened from it is a sheet **over** the panel (the panel is hidden from assistive technology meanwhile); closing it returns to the same panel at the same scroll. "Say it", "Check in" and "Open the private area" close the panel (they leave for the composer, the chat or the area).
- **P2-6** (counts): the count, the sidebar dots and the compact strip all count confirmed asks plus waiting runs, each once, deduplicated by task (a run whose task is already a confirmed row is not a second item; a recheck whose run is waiting now is not rechecked).
- **Sonnet r27**: "Waiting on your answer in #Uni:" is now the question; the cut at "…(paste the same key" was a CSS clamp, now gone; 740×360 clipping: the panel scrolls above its own footer; "Show 15 more" matches by construction and by spec.
- **Codex r27**: no "and N more"-hidden addresses; "unspecified" and "not confirmed since" rows are no longer in Needs you.

## Things the critics should know
- **Rechecks are most of the list today**, and will stay so until rooms write `asked_at` (it is written whenever a room or Aaron writes a task's `next` or `detail`). The recheck list is the way to reach them; "Answer anyway" is one tap there.
- **A private-area ask that is not confirmed is not named anywhere outside its area** (neither in the count nor in the recheck list); inside the area it is an ordinary row.
- **State change:** the vault has no timestamp for a live task's state change (`updated_at` moves with any edit, which is what P1-1 refused to trust), so a plain open → waiting change can't dim a summary; an `asked_at` or a closure can.
- **The wait-claim trigger is still there** (an r26 rule, not a change anywhere below): Uni's real summary dims by it today.
- Related chat is still a lexical check (a task's id, a `#NN`, or two distinctive words), now applied to the feed. It can only take an ask *out* of confirmed, never put one in.
- The closed tasks are read at most every 5 minutes (76 notes on the scratch hub, one request): a closure can take that long to dim a summary.
- The chat read per room is the room's last 200 messages; a read that starts after the ask is a recheck ("read too short to tell").
