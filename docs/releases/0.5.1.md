## Uni 0.5.1

Applets work on a Mac again, and voice notes from a phone go to rooms in the format stock Buzz takes. This is a full app install, not new screens over the air: the app itself changed (shell API 3).

- **Applets on a Mac.** The sandbox self-test failed two checks on a Mac, so applets stayed off there. A sandboxed frame could see the app's message channel, and a frame nested inside it could open a WebRTC connection. Both are now closed in the Mac's web view itself, as on Linux, so every frame loses them. The self-test passes in CI on a real macOS runner, and applets turn on once you run it on your Mac (Settings → Developer → Applets → Run sandbox self-test) and it passes.
- **Voice notes as AAC.** On Android, a voice note is converted on the phone, with its own codecs, to AAC before it is sent. That is the format stock Buzz accepts. You still record the same way, and journals keep the original recording.
- **Long voice notes are cut at pauses.** A note longer than 9:50 goes as one message with its parts in order, each named by its place ("1 of 4 · …"), and each cut falls in a pause, not mid-word. A recording the phone can't convert is sent as it was recorded.
- **Not yet:** Mac and Linux builds still send voice notes as recorded (WebM), which only our own relay takes.

**Needs:** Uni's speech-to-text for the new voice notes (the gateway update hermes-agent 350b5070c5) is staged for the next gateway restart. Ship this release after that restart, so voice notes from the phone are transcribed.
