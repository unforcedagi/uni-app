# Uni release pipeline

**`main` is the release branch.** Day-to-day work lands on `journal` (or feature branches). Promoting to `main` ships: within 30 minutes uni-1 builds the new `main` commit and publishes it as a GitHub release. Installed apps update from there.

## How it runs
- `uni-updater.timer` (systemd user timer on uni-1, linger enabled) runs `scripts/watch-main.sh` every 30 minutes from the dedicated checkout `~/Code/uni-app-pipeline`. Install/refresh it with `bash scripts/install-updater-timer.sh`.
- If `origin/main` has no `uni-v*` tag, the watcher checks it out and runs `scripts/publish.sh`:
  1. Tests: case-collision check, `pnpm typecheck`, `pnpm test`, `cargo test --workspace`.
  2. Version: `scripts/next-version.py` gives one patch above the newest `uni-v*` tag, or `package.json`'s version if that is higher (edit it to jump minor/major). Android versionCode = `1000000 + major*100000 + minor*1000 + patch`. **The pipeline never commits to the repo**; the version is stamped at build time with `tauri --config`.
  3. Builds in parallel: the Mac app on GitHub-hosted `macos-15` (arm64) from the exact `main` SHA and the Android APK on uni-1. The APK is a release build for arm64 only (both devices are arm64-v8a), with the Rust library built for size (LTO, opt-level s, stripped) and compressed in the APK: about 24 MB. `scripts/android-release-build.sh` is that build; `publish.sh` runs it and refuses an APK over 60 MB. Until 0.1.83 it shipped a debug build of 553 MB (T-305). The APK is packaged fresh each time (`outputs/apk` is cleared first), so no dead space from an earlier build is shipped. The Mac workflow checks out Buzz at pinned `5669fdc`; no Mac mini connection is used.
  4. **Waits for the owner's tap (T-335).** The APK is built unsigned (`UNI_ANDROID_UNSIGNED=1`). Once both builds have passed, `publish.sh` asks the sealed broker to sign it; the broker posts one card, "Sign Uni X.Y.Z for Android" (bound to the APK's sha256, version, code and commit), and signs only when the owner approves it. The signer digest check still runs on the result.
  5. Publishes GitHub release `uni-vX.Y.Z` (marked latest) with `Uni-mac-arm64.zip`, `Uni.app.tar.gz` + `.sig`, `uni.apk`, `latest.json` (Mac updater manifest) and `android.json`. The tag is created last, so a failed build leaves nothing behind and the next tick retries.
     It then reads the release back by its tag, and at `releases/latest/download/latest.json` (where installed apps look, cached by GitHub for a while), retrying both with backoff (`scripts/release-check.sh`). Neither skips the device step: a late "latest" only warns, and a release that can't be read by its tag fails the run after the devices.
  6. If the wireless ADB is up on a paired device (Daylight, Pixel 7) and Uni isn't in the foreground, installs the APK directly (never uninstalls).
- **New screens without an APK (T-335 OTA).** Before building, `scripts/release-kind.py` compares the commit with the last APK release (`~/.config/uni/updater/last-apk`, written by `publish.sh` after each APK). When every change since is in the screens (`src/`, `public/`, `docs/`, `scripts/`, Vite and TypeScript config; `package.json` only outside its dependencies) and `SHELL_API` is unchanged, the release is a **screens bundle**: `scripts/ota-bundle.sh` packs `dist/` as `web-X.Y.Z.tar.gz`, the broker posts one card, "Uni screens X.Y.Z over the air" (bound to the archive's sha256, the version, the shell API and the commit), and after the tap signs the channel manifest `web.json` (Ed25519, valid 14 days; the key is sealed in the broker, its public half built into the app). `scripts/ota-verify.ts` checks it against the app's built-in key, then the release carries the Mac assets, `latest.json`, `android.json` (still the last APK), `web-X.Y.Z.tar.gz` and `web.json`. No device installs. At most one bundle a day (`~/.config/uni/updater/last-bundle`, and the broker refuses a second card the same day); a later screens-only commit waits for the next day. Anything else, or anything unknown (no `last-apk`, `UNI_RELEASE_KIND=apk`), is an APK release as above. `publish.sh` refuses to run with `UNI_OTA_CHANNEL` or `UNI_OTA_PUBKEY` set (test builds only).
- Logs: `journalctl --user -u uni-updater.service`; build logs under `~/.cache/uni-release/uni-release-<version>/`.
- Run by hand: `bash scripts/watch-main.sh`. Pause: `systemctl --user stop uni-updater.timer`.

### Signing needs a tap
- A card that is declined, expires or can't be posted (broker down) fails the run before any tag or release: nothing is published. The log line says whether a card was posted and quotes the sealed CLI's last error line. `publish.sh` writes `<sha> <version> <time>` to `~/.config/uni/updater/sign-asked` before it asks and clears it only once the release's tag exists, so an approved APK whose release then fails (a GitHub outage) is not asked for again on its own either.
- The watcher skips that commit with one log line, so a missed card is not rebuilt and asked again every 30 minutes. A new commit on `main` releases as usual. To ask again for the same commit: `UNI_RELEASE_ASK_AGAIN=1 bash scripts/watch-main.sh` (or delete `sign-asked`).
- A build or test failure is not an ask: the next tick retries as before.
- Switches: `UNI_ANDROID_UNSIGNED=1` builds the release APK unsigned (no keystore read; without it a local release build still signs with `$ANDROID_USER_HOME/debug.keystore`); `UNI_SEALED_CMD` names the broker command (default: the sealed CLI on uni-1); `UNI_RELEASE_ASK_AGAIN=1` as above.
- The run holds the release lock while it waits, so the service allows 28 h (`TimeoutStartSec`; re-run `scripts/install-updater-timer.sh` after changing it). The Mac updater signature is not behind the tap yet: `build-mac-hosted.sh` still signs it.

## Devices
- **Mac:** first install from the latest release's `Uni-mac-arm64.zip` (unzip, move to Applications, allow once in Privacy & Security; it is signed with a stable self-signed certificate, not notarized). The app checks `https://github.com/unforcedagi/uni-app/releases/latest/download/latest.json` at launch and every 6 hours, downloads and verifies the signed update, and offers **Restart**.
- **Android screens over the air (T-335):** the app fetches `.../releases/latest/download/web.json` a few seconds after it starts and whenever it comes back to the foreground (at most once a minute). It takes a bundle only if the manifest is signed by the built-in key, not expired, not issued before one it already took, newer than anything it has run, and for its own `SHELL_API`; the archive must match the manifest's sha256. The new screens go in at the next start, or when the app next comes back to the foreground (a reload before anything is touched; never over an open recording). A bundle that doesn't report ready after two starts, or whose own code refuses the shell, is dropped and the app goes back to the last good bundle (else the built-in screens). Settings and the sign-in screen say which screens are running ("Screens 0.3.8 · over the air"). A newer APK always wins over an older bundle. The Mac keeps its own updater (the full app, above): sharing it was not trivial, since the Mac's updater key isn't behind the tap yet.
- **Shell API:** `SHELL_API` (`src-tauri/src/ota.rs`, `src/ota.ts`) names the shell's contract with the screens; `src-tauri/shell-api.txt` records the commands (with their arguments and results), plugins, URI schemes and capability files for each number. `pnpm test` fails when that contract changes without a new number, or when a block that shipped is edited: bump the number in both files and add a block (`node --experimental-strip-types scripts/shellApi.ts` prints it). A change inside a returned struct isn't seen; bump by hand.
- **Daylight:** the app checks `.../releases/latest/download/android.json` and shows **Download APK** for newer versions (Android requires one confirmation per install), unless the ADB path above already installed it. The APK is signed with the original `debug.keystore` key, which moves into the sealed broker (T-335; `publish.sh` pins its certificate digest); keep that key or updates stop installing over the existing app.
- **Tailnet download page:** `publish.sh` copies the APK to `~/.local/share/uni/apk` (shared on the tailnet by `tailscale serve`); a failed copy only warns. Builds 0.1.2-0.1.5 polled a host that is gone, so they no longer get pointers.

Release builds run `scripts/check-release-dist.sh` as the Tauri `beforeBuildCommand`: it deletes `dist/`, builds with `UNI_T76` unset and fails if `__T76_MOCK` is in `dist/assets`.

## Signing and hosted build security
The updater private key and stable self-signed signing certificate remain on uni-1 in `~/.config/uni/updater/` (`uni.key`, `macsign.p12`, `macsign.pass`). `scripts/build-mac-hosted.sh` uploads them as **temporary GitHub environment secrets**, dispatches `.github/workflows/mac-build.yml` for the exact main SHA, waits for the run, downloads the three Mac assets and deletes the secrets on exit (including failure). The environment `uni-mac-signing` must have a custom deployment-branch policy allowing **only `main`**; the helper refuses to run if that policy changes. GitHub decrypts these credentials on its hosted runner while building; this is a trust tradeoff, not end-to-end private signing. Do not run this workflow on unreviewed main code, grant untrusted collaborators workflow write access, or widen the environment branch policy. If a host or workflow is compromised during the short secret window, rotate the updater key (requiring manual reinstall) and signing certificate. No signing secret is stored persistently in GitHub after the helper exits.

The workflow checks the release version in `Uni.app`, verifies the stable certificate SHA-1 `E82AA2442F66F08F3772C9D6F7ADD877A1290125`, and uploads `Uni-mac-arm64.zip`, `Uni.app.tar.gz`, and `Uni.app.tar.gz.sig` as a short-lived Actions artifact. The local publisher still stamps/builds Android on uni-1 and only creates a release/tag after both platforms succeed. An interrupted host can leave temporary secrets behind; check `gh secret list -R unforcedagi/uni-app -e uni-mac-signing` and delete the three `MACSIGN_P12_BASE64`, `MACSIGN_P12_PASSWORD`, `TAURI_SIGNING_PRIVATE_KEY` secrets before retrying. The environment must be created with a main-only custom branch policy before enabling the timer.
